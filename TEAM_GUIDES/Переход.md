# Переход Arkadi03/SpeechNote-Team на v2

**Статус — план для согласования.** Готовая папка v2 служит рабочим образцом и источником заготовок. История разработки команды остаётся в [существующем репозитории](https://github.com/Arkadi03/SpeechNote-Team). Локальная командная копия указывает на этот origin и ветку team-main, HEAD — `9bd8a6dc71d47b98bc8df7166dfc613c117cda46`. Сведения о четырёх уже отправленных приглашениях предоставил координатор.

## До начала работ

1. Соберите список из шести GitHub-логинов, включая координатора. В Settings → Collaborators сравните с ним принятые и ожидающие приглашения. Всего нужны **пять** коллег координатора; если четыре приглашения принадлежат четырём разным участникам списка, пригласите ещё одного. Сначала подтвердите состав команды.
2. В существующем клоне проверьте адрес через `git remote -v` и локальные правки через `git status --short`. Обнаруженная локальная папка .idea относится к настройкам IDE. Для перехода удобен свежий клон в новой папке, особенно если кто-либо уже начал старое задание.
3. После согласования обновите сведения командой `git fetch origin`, посмотрите открытые PR на GitHub и выполните `git log -5 --oneline origin/team-main`. Команда `git merge-base --is-ancestor 9bd8a6d origin/team-main` должна завершиться с кодом 0. Уточните у авторов, какие уже сделанные изменения войдут в новый план. Принятые и незавершённые работы указывайте с их настоящими авторами. При расхождении истории сначала разберите его с командой.
4. Только после разрешения создайте общую интеграционную ветку **от актуального** origin/team-main: `git switch -c integration/v2 origin/team-main`. Затем `git push -u origin integration/v2`. Первичный fork, смена origin и перенос чужой папки .git для этого перехода не нужны.

Ранее задания по странице и CSS были раздельными. Их получает участник 1. Микрофон переходит к участнику 2, файлы, расшифровка и экспорт — к участнику 3, прежние статусы и справка — к участнику 4. Участники 5 и 6 отвечают за новый API и интеграцию. Старые карточки доступны в истории стартового коммита. Новый план не требует переименования репозитория, удаления старых веток или повторной выдачи существующих доступов.

**Порядок для участника в PyCharm.** Примите приглашение в своём GitHub. Откройте Settings → Version Control → Git → Test, затем GitHub → Add → Log In via GitHub. Через Clone Repository клонируйте адрес команды. В Terminal проверьте `git config --get user.name` и `git config --get user.email`; при необходимости задайте личные значения через `git config --local`. В меню веток переключитесь на origin/integration/v2, создайте **New Branch** с именем своей карточки и опцией Checkout. Эквивалент, например, для участника 3: `git switch -c v2/transcript origin/integration/v2`.

Для каждого шага откройте **свой файл** в клоне и соответствующий файл готовой v2 для сверки. Реализуйте изменение, сохраните, выполните указанную проверку. Пока смежный модуль ещё не принят, для функциональной пробы можно подставить свой файл в отдельную временную копию v2. В PR укажите, в каком составе проверяли. Готовый эталон и папку .venv оставьте на месте.

После шага нажмите **Ctrl+K**, отметьте только его файлы и прочитайте diff. Нажмите Commit, используя название выполненного изменения. После четырёх шагов проверьте `git log --oneline origin/integration/v2..HEAD`, затем **Ctrl+Shift+K → Push** в личную ветку на origin. На GitHub выберите Pull requests → New pull request, базу **Arkadi03/SpeechNote-Team:integration/v2** и свою ветку. Приведите результаты собственных проверок и фразу о происхождении заготовок. Не включайте токены, .env, HAR, модели, .venv и настройки IDE.

## Приёмка и возврат в team-main

Координатор проверяет шесть PR, принадлежность коммитов, затронутые файлы и взаимосвязи между модулями. Сначала удобно принять серверную часть (2), работу с текстом (3), настройки (4), генерацию (5), затем подключение HTML и сборщика ресурсов (1), запуск и интеграционные проверки (6). Временная ветка предназначена для сборки всех компонентов. Общую team-main переключайте только после итоговой проверки.

Для сохранения индивидуальных коммитов используйте Create a merge commit. После объединения проверьте весь маршрут из README, сравните содержимое web с ZIP и запишите **фактические** результаты для Ubuntu, LLM и двухголосой записи. Откройте один итоговый PR **integration/v2 → team-main**. Координатор и команда подтверждают готовность перед merge. Если потребуется исправление уже принятой версии, используйте обычный корректирующий PR или revert через PR. Force-push и сброс team-main здесь не требуются.
