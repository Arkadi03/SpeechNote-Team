# Подготовка репозитория и приём семи работ

Координатор также выполняет одну из семи карточек. Сначала публикуется настоящая общая заготовка. Затем даже координатор делает три личных изменения в отдельной ветке.

1. На GitHub откройте [WhisperLiveKit](https://github.com/QuentinFuxa/WhisperLiveKit), нажмите **Fork → Create a new fork**, выберите свой аккаунт или организацию и название **SpeechNote-Team**. Fork содержит общую историю с локальной копией. Скопируйте URL кнопкой **Code → HTTPS**.
2. В PyCharm откройте подготовленную папку **SpeechNote-Team** рядом с эталоном. В Terminal выполните команды ниже. Подставьте имя, email и фактический URL. Ожидаемая ветка — team-main. Перед добавлением origin список remote в подготовленной копии пуст.

```powershell
git branch --show-current
git remote -v
git config --local user.name "Ваше имя"
git config --local user.email "Ваш подтверждённый email"
git remote add origin https://github.com/ВАШ-АККАУНТ/SpeechNote-Team.git
git status --short
git add -- .gitignore README.md TEAM_GUIDES examples/speechnote-ru.wav start-speechnote.ps1 whisperlivekit/web
git diff --cached --stat
git commit -m "Добавить подготовленную стартовую основу и семь учебных карточек"
git push -u origin team-main
```

3. Проверьте на GitHub ветку team-main, наличие TEAM_GUIDES и исходной LICENSE. Сделайте team-main основной в **Settings → General → Default branch**, если хотите открывать её по умолчанию. В **Settings → General → Pull Requests** включите **Allow merge commits**.
4. Откройте **Settings → Collaborators** (в организации — **Collaborators and teams**) → **Add people**. Пригласите шесть других участников по их GitHub-логинам. Для организации выберите доступ Write. Дождитесь принятия приглашений. Разошлите один URL репозитория, название базовой ветки и персональные номера карточек.
5. Каждый участник начинает с опубликованной team-main. Все семь заданий меняют разные файлы и могут выполняться параллельно. На каждом PR проверьте base/head, авторов трёх содержательных коммитов, список файлов, отметку об использовании заготовок и личный результат проверки. Если участник изменил чужой файл, попросите его исправить свой PR.
6. Для каждого одобренного PR выберите **Merge pull request → Create a merge commit → Confirm merge**. Так GitHub сохраняет индивидуальные коммиты. Удобно принять 2–7, затем 1. Запишите семь ссылок для защиты.
7. В локальной командной копии после сохранения своих изменений перейдите на общую ветку: `git switch team-main`, затем `git pull --ff-only origin team-main`. Запустите эту копию по README, выберите русский WAV, проверьте микрофон, TXT и очистку. Эта проверка относится к работам студентов после реального объединения.
