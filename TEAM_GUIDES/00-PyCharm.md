# Работа участника в PyCharm на Windows

## Подключение

1. Примите приглашение координатора в GitHub под своим аккаунтом. Откройте командный репозиторий и скопируйте HTTPS-адрес через **Code → HTTPS**.
2. В PyCharm откройте **File → Settings → Version Control → Git**. Нажмите **Test**. Если Git не найден, укажите путь к установленному git.exe. В разделе **GitHub** нажмите **+ → Log In via GitHub**. В браузере проверьте имя своего аккаунта и разрешите JetBrains вход. Вернитесь в PyCharm.
3. На стартовом экране выберите **Clone Repository** (также **File → New → Project from Version Control**). Вставьте скопированный URL. Выберите новую папку, например `Documents/SpeechNote-Team`, и нажмите **Clone**. Дождитесь открытия проекта.
4. Внизу откройте **Terminal**. Проверьте `git remote -v`: адрес origin должен вести в командный репозиторий. Задайте авторство только для этого клона, заменив примеры своим именем и подтверждённым адресом из GitHub → Settings → Emails.

```powershell
git config --local user.name "Ваше имя и фамилия"
git config --local user.email "ваш-адрес-из-GitHub"
git config --get user.email
```

## Своя ветка

В верхней панели нажмите название текущей ветки. Выберите **Remote Branches → origin/team-main → Checkout**, если локальной team-main ещё нет. Если она есть, выберите **Local → team-main → Checkout**. Выполните **Git → Pull**. Снова откройте меню веток, выберите **New Branch**, введите имя из своей карточки и оставьте включённым **Checkout branch**. Проверьте в Terminal командой `git branch --show-current`. Работайте именно в этой ветке.

## Три изменения

Откройте свою карточку 01–07. Выполняйте по одному шагу. Код внутри рамки копируется без тройных обратных кавычек. После вставки нажмите Ctrl+S, откройте командную страницу на порту 8001 и выполните указанную проверку. Для JavaScript-консоли браузера нажмите F12 → Console. Поясните напарнику, что поменялось и по какому признаку это видно.

После успешного шага нажмите **Ctrl+K**. В списке Changes отметьте только свой файл. Щёлкните по нему, чтобы посмотреть добавленные и удалённые строки. Введите сообщение из карточки и нажмите **Commit**. Коммит сохраняется локально. Повторите для второго и третьего шагов. Перед отправкой в Terminal выполните `git log --oneline origin/team-main..HEAD`: должны быть три ваши записи.

## Push и pull request

1. Нажмите **Ctrl+Shift+K** (Git → Push). Проверьте слева имя своей ветки, справа **origin** и такое же имя ветки. Нажмите **Push**. При запросе авторизации используйте свой аккаунт. При сообщении об отказе проверьте принятие приглашения и адрес origin.
2. Откройте командный репозиторий в браузере → **Pull requests → New pull request**. В fork GitHub может предложить родительский репозиторий. Выберите **base repository** команды, **base: team-main**, **head repository** команды и **compare** со своей веткой. Проверьте вкладки с тремя коммитами и изменённым файлом.
3. Нажмите **Create pull request**, укажите название задания. Опишите входные данные, собственные действия, наблюдаемый результат и затруднения. Пример раскрытия вклада: «Использовал выданные заготовки шагов 1–3. Сам внёс изменения, проверил … и получил …». Сохраните ссылку. Исправление по замечанию вносите в ту же ветку и повторите push — PR обновится.
4. Если разница пустая, перепроверьте обе ветки и факт push. При конфликте обратитесь к координатору с именем файла и текстом ошибки. На этом этапе история каждой ветки нужна для защиты.
